# 核心 ESP 排名优先交付计划

## 总原则

已有代码和功能不废弃，全部保留为后续阶段能力；但核心 ESP 排名评价必须先形成独立、可运行、可演示、可交付的主产品。
后续扩展不得反向阻塞核心排名主流程。

核心交付链固定为：

`公开文档采集 → 证据候选 → 指标值 → ESP评分 → 研究排名 → 证据可追溯报告`

## 分期归属

### P0：核心排名交付（当前最高优先级）

目标：交付一个能够真实处理公开文档并生成 ESP 排名的系统。

范围：

- 固定一个报告期和一个可核验公司样本，先以25～50家能源上市公司为交付样本；
- 优先实现10～15项公开资料稳定、口径明确的核心定量指标；
- 完成文档发现/下载、Hash校验、文本抽取、证据候选和评分；
- 输出公司总分、E/S/G分项、指标贡献、覆盖率、缺失项和排名；
- 提供 HTML、CSV、JSON 三种结果，并显示研究预排名水印；
- 保留一个高影响/冲突审核队列，但人工审核只用于修正关键结果，不要求全量签名；
- 页面必须能从排名下钻到指标、证据页码和计算过程。

P0 不包含：632家公司正式覆盖、43项定性全量签名、双审仲裁、正式发布授权和专利效果实验。

P0 验收：给定一批公开报告，单条命令可重复生成排名和证据报告；结果可解释、可追溯，且不打开代码即可完成演示。

### P1：研究版扩展

沿用现有模块：`collector`、`extraction`、`scoring`、`ranking_analysis`、`dashboard`、`evidence_graph`、
`incremental`。

目标：

- 扩展至37项定量指标和更大公司池；
- 增加缺失策略、敏感性、排名稳定性和影响优先级；
- 完善审核工作台和企业证据链；
- 研究域与正式域使用不同算法版本和输入快照。

### P2：正式评价治理

沿用现有模块：`universe_builder`、`universe_review`、`issuer_continuity`、`qualitative_review`、
`dual_review`、`review_batch`、`release_guard`、`completion`。

目标：

- 冻结正式公司池和报告状态；
- 完成43项定性指标规则化、单审、双审和仲裁；
- 建立签名、冻结、版本Hash和正式发布授权；
- 生成正式审计版排名。

### P3：研发增强与专利取证

沿用现有模块：`evidence_experiment`、`e2_experiment`、`auto_stage`、`stage_orchestrator`及相关实验产物。

目标：

- 证据约束图、审核调度和增量重算技术效果实验；
- 双算法域隔离、篡改防护和可复现实验；
- 专利交底、发明人贡献记录和对照实验材料。

这些能力保留并持续研发，但不得成为 P0 排名交付的前置条件。

## 工程隔离规则

1. P0 只依赖稳定的采集、抽取、评分和报告模块；
2. P1/P2/P3 通过独立命令、输入快照和输出目录接入，不直接修改 P0 结果；
3. 研究结果和正式结果使用不同状态、版本号和水印；
4. 任何新增功能必须标记所属阶段、输入依赖和是否阻塞 P0；
5. 旧版本候选文件保留为审计历史，但主流程只读取明确标记的 current snapshot，避免 v2～v22 混用；
6. 每个阶段均可单独测试、演示和验收，阶段之间通过稳定 CSV/JSON 契约连接。

## 当前执行顺序

1. 固定 P0 样本、报告期、指标子集和评分规则；
2. 从现有采集和抽取能力中挑出稳定路径，完成端到端排名；
3. 把现有 Demo 改为 P0 排名交付入口，明确显示证据和研究状态；
4. P0 验收后自动进入 P1，逐步接回审核、敏感性和全量覆盖能力；
5. P2/P3 继续保留原计划，但不得再改变 P0 的交付定义。

## P0 客户评审 Demo 节点

以当前已有真实数据和排名产物为基础，P0 Demo 不等待632家公司正式签名，先以“研究预排名系统”交付设计评审。

### D1：系统骨架可走通

交付内容：一个入口页面串联数据源、文档、证据、指标、排名、审核和发布门禁；所有入口为结构化页面，
不要求打开代码或原始JSON。

### D2：真实企业闭环

交付内容：选择一家真实企业，完成“排名 → E/S/G分数 → 指标明细 → 证据页码 → 缺失/冲突 → 审核任务 →
敏感性 → 当前不可正式发布原因”的现场演示。

当前已增加 `/demo/complete-chain`，从真实研究输入中筛选目标年度文档已采集、观测数不少于67项且有排名明细
的企业作为首批完整数据链演示 cohort；当前可筛出7家，点击企业可进入 `/demo/company/{stock_code}`。

另增加 `/demo/ranking-center` 作为一键排名入口：点击后读取当前版本化研究输入，进入研究预排名结果，并同时
展示任务覆盖率、待补数据、证据冲突和正式发布状态。数据不全时仍允许研究预排名，但必须保留缺失提示和不可正式
发布状态；按钮不会生成正式签名或修改正式数据。

企业详情现在按公司/指标连接研究观测和`document_index.csv`：显示来源PDF、来源URL、页码、抽取原文和文件SHA-256；
无法连接来源的指标显示“来源缺失”，不再把只有分数的记录视为完整证据链。

### D3：客户评审包

交付内容：启动脚本、演示数据说明、5～10分钟演示脚本、客户问题清单、研究/正式边界说明和已知限制清单。

按当前代码基础，D1和D2属于短周期收敛工作，预计连续研发 **2～4个工作日**；D3随后再用 **1个工作日**
固化。若客户要求正式排名、全量公司和真实签名，则不属于这个 Demo 节点，必须进入 P2，时间由外部资料和审核人决定。

### Demo 完成判定

客户可以在不查看代码的情况下回答：系统采集了什么、某个分数从哪里来、哪些地方不确定、如何审核、为什么
当前能或不能发布，以及下一步要补什么资料。满足这些条件才称为“真正 Demo”，而不是页面集合。
