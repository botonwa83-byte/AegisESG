# Aegis ESG 完成路线图

## 产品定位与设计原则

本项目不是“无人值守地复刻第三方榜单”。公开资料不包含完整原始数据、缺失值规则和部分评分参数，
强行全自动只会制造不可验证的精确数字。系统应定位为**人机协同、可审计的独立ESG评价生产线**：

- 机器负责公司池对账、文档采集、严格抽取、公式派生、统计评分、冲突检测和任务调度；
- 人只处理主体身份、口径冲突、重大定性判断和抽样质量控制；
- 系统可以自动生成带限制说明的研究版排名，但正式发布版必须通过风险分级审核和冻结门禁；
- “未检出证据”不自动等同于“表现为零”，缺失值策略必须版本化并在结果中披露；
- 排名必须同时展示覆盖率、可信等级和敏感性，避免把数据完整度误当ESG表现。
- 核心模块按可申请发明专利的技术方案研发，功能、测试、对照实验和研发留痕同步完成；专利策略见
  [发明专利技术方案与研发取证计划](patent-strategy.md)。

## 三种输出级别

1. **开发预览**：用于验证代码和数据分布，可包含pending，不对外发布，不称为榜单；
2. **研究版排名**：只使用自动确认和已签名数据，应用明确的缺失值策略，附覆盖率、置信区间、
   排名稳定性和方法限制；允许在公司池未达到632家时生成，但标题必须标注样本范围；
3. **正式审计版**：632家主体冻结，高风险项审核完成，输入和代码版本冻结，可对外发布。

## 正式完成定义

“开发完成”不是抽取程序能够运行，而是以下六道门禁全部通过：

1. **主体门禁**：632个唯一公司主体完成行业纳入、ST排除、A/H去重和来源审计；
2. **文档门禁**：632家公司2025年年报状态全部闭环，文件具备URL、SHA-256和有效性记录；
3. **定量门禁**：37项均达到版本化最低统计人口；冲突和高影响异常已审核，真实空窗按缺失策略处理；
4. **定性门禁**：43项均完成规则化判断或风险分级审核，重大判断完成双签或仲裁；
5. **审核门禁**：不存在高风险未签名冲突、开放批次或待仲裁项；低风险自动决定完成统计抽样验收；
6. **发布门禁**：冻结主体、文档、观测、方法论和代码版本，并通过`score --release`。

## 调整后的执行阶段

### M1：完成度审计与回归基线

状态：已完成。

交付物：

- `aegis-esg audit-completion`统一审计命令；
- 六道门禁JSON报告；
- 完成与阻塞场景自动化测试。

验收：全量测试通过，当前审计报告可重复生成。

### M2：让系统真正生成可信的研究版排名

任务：

1. 为评分命令增加`preview`、`research`、`release`三种显式模式，禁止模式含义模糊；
2. 将缺失处理从评分器中的隐式0分改为版本化策略：原始0分、同指标中性分、权重重分配等策略
   分开实现，正式方法论只选择并冻结其中一种；
3. `research`模式只接受自动确认和人工确认数据，并设置公司覆盖率、指标最低人口和冲突门槛；
4. 输出公司数据覆盖率、指标人口、可信等级及“不得作为正式榜单”的水印；
5. 增加敏感性分析：比较不同合理缺失策略下的名次变化，标记不稳定公司；
6. 以当前614家公司生成第一版研究排名，验证端到端自动化，而不是等待所有人工审核后才首次算分。
7. 将`audit-completion`升级为v2风险门禁，替代旧的逐格全量完成判断。
8. 完成缺失策略与双算法隔离实验E4/E5，冻结实验输入、代码版本和结果。

验收：单条命令可从冻结的研究输入生成CSV、JSON、HTML、质量报告和敏感性报告；测试证明pending
不会被静默当作确定的0分，低覆盖公司不会获得无提示的精确名次。

### M3：冻结632家公司主体表

任务：

1. 导入完整企业名录，与历史636家、当前614家及四交易所8,323只证券三方对账；
2. 补齐18家公司，完成港股中文全称、行业和发行人连续性审核；
3. 对A/H组合成组签名，固定A股优先，不以模糊名称自动合并；
4. 重建正式公司池及公司池审计。

外部依赖：完整企业名录和具名审核人的签名决定。系统不得代签。

### M4：报告状态闭环

任务：

1. 为新增18家公司发现、下载并校验2025年年报及ESG报告；
2. 对`00702.HK`、`01101.HK`保留有证据的目标年度缺失状态；
3. 增量文本化并重建文档覆盖审计，修复错误稿件或报告期混入。

验收：632家公司均为已采集或有签名缺失结论，下载失败队列清零或有可审计终态。

### M5：定量自动化与风险分级审核

任务：

1. 按“预计排名影响×证据冲突×指标权重”重排145个冻结阻塞组，而不是平均审核所有任务；
2. 高风险冲突逐项签名；一致多来源和严格公式派生采用抽样审核，抽样失败才扩大审核范围；
3. 按关键指标缺口、指标权重和可派生性排序扩展严格规则；
4. 真实空窗由缺失策略处理，只有“不适用”判断和可能改变排名的异常缺失要求人工签名；
5. 每轮重建候选覆盖、审核分层、研究排名、敏感性和冻结审计。
6. 建立证据约束图原型，执行抽取精度实验E1和审核调度实验E2。

验收：37项均达到最低统计人口；高风险队列为0；自动决定抽样准确率达到冻结阈值；缺失和薄样本
对名次的影响在敏感性报告中可见。

### M6：定性规则化与风险分级审核

任务：

1. 把43项拆成可客观判定、需语义判断、必须专家判断三类；
2. 对可客观判定项建立正证据、反证据和适用范围规则，机器给出可审计决定；
3. 对语义判断项使用结构化证据包和单签抽查，不要求10,538组无差别逐项审核；
4. 80/100分、偏离建议档、高权重弱证据及排名敏感项必须二审，分歧交第三人仲裁；
5. 没有证据保持missing，不因关键词未命中自动打0分；缺失策略在研究版和正式版中统一披露；
6. 从首批500组建立人工基准集，测量规则精确率和审核一致性，再决定各类自动化阈值。

验收：规则化类别达到约定抽样精确率；高风险项无pending；批次全部closed；不存在开放二审或仲裁；
每个非零分值均可追溯到证据。

外部依赖：至少两名真实审核人，发生分歧时需要第三名仲裁人。

### M7：冻结与正式发布

任务：

1. 合并定量和定性确认观测，拒绝同组冲突，并冻结缺失值策略；
2. 冻结公司池、文件Hash、观测Hash、方法论版本、代码提交和统计参数；
3. 执行质量、完整性、异常值、薄样本、敏感性和历史趋势审计；
4. 运行正式评分，输出632家全量结果和前200 CSV、JSON、HTML；
5. 保存发布清单和可复现命令。
6. 完成依赖图增量重算实验E3和双算法域隔离复验E5，形成专利技术效果报告。

验收：六道完成门禁全部为`complete=true`，研究版与正式版边界清晰，
`score --release --expected-companies 632`成功。

## 人工审核预算原则

人工审核不再以“把49,120个格子全部签一遍”为目标，而集中在四类任务：

1. 会改变公司池的行业归属、ST状态和A/H主体关系；
2. 同一公司指标出现实质冲突，且指标权重或排名影响较高；
3. 定性80/100分、高权重弱证据或审核人分歧；
4. 自动规则的分层随机抽样与失败后的扩大检查。

系统必须记录自动决定比例、人工决定比例、抽样错误率、审核人一致率和排名敏感项数量。只有这些
质量指标达标，减少人工审核才是可信的自动化，而不是把人工判断隐藏进代码。

## 每轮开发纪律

1. 先运行全量测试和完成度审计；
2. 一次只选择能够减少明确阻塞计数的任务；
3. 规则新增必须包含真实版式正例、污染口径反例和全量零丢失比较；
4. 候选、预览、签名确认和正式冻结数据必须分文件保存；
5. 每轮更新覆盖摘要和完成度报告；
6. 未取得审核人身份、时间、理由时不得生成签名决定；
7. 六道门禁未全部通过时不得对外称为正式榜单。
8. 专利相关功能必须保留旧方案失败样例、对照实验、输入Hash、代码版本和发明人贡献记录。
9. 在申请日确定前，不公开披露未申请核心机制的实现细节；具体公开边界交专利代理师确认。
