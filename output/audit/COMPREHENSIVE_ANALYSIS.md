## 二、根本问题分析

### 问题1：单位不匹配（最关键）

**标准要求的单位**：
- 温室气体：吨CO2e/万元营业收入
- 能源强度：吨标准煤/万元营业收入
- 水资源：立方米/万元营业收入

**企业实际披露单位**：
- 温室气体：吨CO2e/**百万元**营收 ⚠️
- 能源强度：tce/**百万元** ⚠️
- 水资源：吨/**百万元** ⚠️

**换算关系**：
```
1吨/百万元 = 0.01吨/万元
百万元 = 100万元
需要系数：÷100 或 ×0.01
```

**当前问题**：
- DirectRule的factor固定为1.0
- 没有根据单位动态调整
- 提取的数值可能大100倍！

### 问题2：年份选择（已修复）

**实际表格格式**：
```
温室气体排放强度 吨CO2e/百万元 38.02 44.11
                            ↑    ↑
                          2024  2025
```

**修复**：
- ✅ 已修改规则匹配行尾最后一个数值
- ✅ 提取2025年数据

### 问题3：表格识别率低

**原因**：
- 格式多样：有表头、无表头、紧凑型
- 关键词变体：能源消耗/能源强度/综合能耗
- 单位位置：可能在表头、可能在数据行

## 三、解决方案

### 方案A：完善DirectRule的factor（推荐）

**核心思路**：
根据匹配到的单位文本，动态选择换算系数

**实现方式**：
需要修改extraction.py的逻辑，在匹配后检查单位：
```python
# 伪代码
if "百万元" in matched_text:
    factor = 0.01  # ÷100
elif "万元" in matched_text:
    factor = 1.0
else:
    factor = 1.0  # 默认
```

**问题**：
- DirectRule当前只有一个固定factor
- 需要增强提取逻辑

### 方案B：在规则中明确单位换算（当前方案）

**实现**：
在_rule和DirectRule中添加更多单位变体及其换算系数

**优点**：
- 不需要修改核心逻辑
- 配置化

**缺点**：
- 需要枚举所有可能的单位组合
- 维护成本高
